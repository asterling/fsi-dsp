# Confluent Platform on LinuxONE — FSI Hardened Deployment Runbook

This runbook walks a complete deployment of Confluent Platform 8.2.0 on Red Hat
OpenShift Container Platform 4.14+ on IBM LinuxONE / s390x, with four FSI hardening
controls applied (RBAC, mTLS, Schema Registry governance, audit logging).

> **Notation:**
> - Steps marked `[UPSTREAM]` follow Mondics's runbook from `base/upstream/`
>   (see `base/cluster-linking-runbook.md` after fetching).
> - Steps marked `[GOODLABS]` are GoodLabs additions — FSI hardening controls
>   not present in the upstream reference.

---

## Prerequisites

- RHOCP 4.14+ cluster on IBM LinuxONE (s390x workers)
- FIPS mode enabled at OCP install time (required for `spec.tls.fips.enabled` — see `layers/02-tls/README.md`)
- Cluster admin `kubeconfig` and `oc login` session
- `flox activate` completed in this directory (installs tools + fetches upstream)
- LDAP directory accessible from the OCP cluster network (for MDS/RBAC)
- Secrets populated from `layers/*/secrets.template/` (replace all `<PLACEHOLDER>` values)

## Step 0: Environment setup [GOODLABS]

```bash
# Activate the Flox dev environment — installs all required tools
# and runs base/fetch-upstream.sh to populate base/upstream/
flox activate

# Verify tools
oc version
kustomize version   # must be >=5.3 for kind:Component support
confluent version
```

---

## Step 1: Install the CFK operator [GOODLABS]

The CFK operator manages all Confluent components. Use the existing Ansible role —
do NOT use raw `helm install` (the role is readiness-gated and sets OLM labels).

```bash
# From the repo root:
ansible-playbook -i inventory/linuxone.yml ansible/playbooks/cfk_operator.yml \
  -e cfk_namespace=confluent \
  -e cfk_version=3.2.x
```

Reference: `ansible/roles/cfk_operator/` — the role installs via OLM or Helm,
waits for operator readiness, and configures the `ConfluentPlatform` CRD admission webhook.

---

## Step 2: Prepare secrets [GOODLABS]

Each layer has a `secrets.template/` directory. Copy the templates and fill in real values:

```bash
# Layer 01 — RBAC: MDS token keypair + LDAP credentials
cp layers/01-rbac/secrets.template/mds-token-keypair.yaml /tmp/mds-token-keypair.yaml
cp layers/01-rbac/secrets.template/ldap-credentials.yaml  /tmp/ldap-credentials.yaml
# Edit /tmp/*.yaml — replace every <PLACEHOLDER> with the real value
oc apply -f /tmp/mds-token-keypair.yaml -n confluent
oc apply -f /tmp/ldap-credentials.yaml  -n confluent

# Layer 02 — TLS: CA cert + per-component cert PEMs
# Generated by ansible/roles/cp_mtls or LinuxOne/ansible-mtls/:
ansible-playbook -i inventory/linuxone.yml ansible/playbooks/cp_mtls.yml \
  -e mtls_namespace=confluent
# The role creates the K8s Secrets directly — no manual copy needed.
```

## Step 3: Deploy base + FSI layers (dry run first) [UPSTREAM + GOODLABS]

```bash
# Fetch upstream if not already populated (normally done by flox activate)
bash base/fetch-upstream.sh

# Dry-run against the cluster to exercise CFK CRD admission
kustomize build overlays/prod | oc apply --dry-run=server -f - -n confluent

# Apply for real
kustomize build overlays/prod | oc apply -f - -n confluent
```

For the base steps (Kafka, SR, Connect, ControlCenter CRs and their underlying config),
refer to Mondics's runbook at `base/upstream/cluster-linking-runbook.md` (populated
after fetch). The GoodLabs layers patch those CRs declaratively — you do not need to
hand-edit upstream manifests.

## Step 4: Wait for operator reconciliation [UPSTREAM]

```bash
# Watch component status — all should reach Running/Ready
oc get kafka,schemaregistry,connect,controlcenter -n confluent -w

# CFK condition to check:
oc get kafka kafka -n confluent -o jsonpath='{.status.phase}'
# Expected: RUNNING
```

## Step 5: Validate RBAC layer [GOODLABS]

```bash
bash layers/01-rbac/validate-rbac.sh
```

Asserts:
- ConfluentRolebindings exist for all 6 FSI roles
- `producer-only` principal cannot consume (403)
- `auditor-readonly` is NOT bound to `payments.*` topics (D-02)

Reference: `ansible/roles/cp_rbac/` provides an optional drift-reconciliation pass
(LIST/DIFF/ADD/REMOVE) after initial apply — run it to detect configuration drift.

---

## Step 6: Validate mTLS + FIPS layer [GOODLABS]

```bash
bash layers/02-tls/validate-mtls.sh
```

Asserts:
- Client with no cert → SSL handshake rejected
- Client with valid cert → `kafka-broker-api-versions` returns broker metadata

See `layers/02-tls/README.md` for the manual cert rotation procedure (fallback if
cert-manager is not available).

---

## Step 7: Validate Schema Registry governance layer [GOODLABS]

```bash
bash layers/03-schema-governance/validate-schema-governance.sh
```

Asserts:
- Subject with invalid name → rejected
- Incompatible schema change → FULL_TRANSITIVE rejects registration
- Hard-delete attempt by non-privileged principal → 403

The SR bootstrap Job (`job-sr-bootstrap.yaml`) runs once on apply to set
FULL_TRANSITIVE globally. It is idempotent (`restartPolicy: Never`).

---

## Step 8: Validate audit logging layer [GOODLABS]

```bash
bash layers/04-audit/validate-audit.sh
```

Asserts:
- Authentication attempt → event lands in `_confluent-audit-log-events`
- Authorization decision → event lands in `_confluent-audit-log-events`
- Schema change → event lands in `_confluent-audit-log-events`

Check SIEM delivery:
- Splunk: see dashboards in `observability/splunk/`
- Dynatrace: see dashboards in `observability/dynatrace/`

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|-------------|-----|
| `spec.tls.fips.enabled` has no effect | OCP cluster not installed in FIPS mode | Re-install OCP with `fips: true` in install-config.yaml |
| MDS fails to start | LDAP not reachable or wrong credentials | Check `ldap-credentials` Secret; verify network policy allows MDS→LDAP |
| `kustomize build` fails with unknown field | Stale CRD schema | `oc get crd kafka.platform.confluent.io -o json` to verify installed version |
| Audit topic not receiving events | layer 04 applied before layer 01 | Re-apply in order 01→02→03→04; check component ordering in overlay kustomization |
| SR bootstrap Job not completing | s390x image pull failure | Verify UBI9 image is available; see `layers/03-schema-governance/job-sr-bootstrap.yaml` |
