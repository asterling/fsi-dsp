# Confluent Platform on IBM LinuxONE — FSI Hardened Accelerator

Production-grade Confluent Platform 8.2.0 on Red Hat OpenShift on IBM LinuxONE / s390x,
with four FSI hardening controls (RBAC, mTLS, Schema Registry governance, audit logging)
layered as Kustomize Components on top of IBM's reference implementation.

## Architecture

```
overlays/{dev,prod}/kustomization.yaml   ← the only buildable Kustomization
    └── resources: ../../base            ← Mondics's CP 8.2.0 manifests (fetched)
    └── components:
            ├── 01-rbac    (MDS + LDAP IdP + 6 ConfluentRolebinding CRs)
            ├── 02-tls     (mTLS secretRef + FIPS + cert-manager CRs)
            ├── 03-schema-governance  (FULL_TRANSITIVE + SR bootstrap Job)
            └── 04-audit   (audit router + KafkaTopic + Connect SIEM sinks)
```

Component order encodes dependencies: RBAC (ConfluentServerAuthorizer) must apply
before audit (event router); TLS secrets must exist before SR governance bootstrap Job.

## Hardening layers

### Layer 01: MDS RBAC

**Why:** CP without RBAC runs as an open cluster — any authenticated principal has
unrestricted topic access. SOX, FFIEC, and PCI-DSS § 7 require least-privilege access.

**What:** Enables MDS (Metadata Service) with LDAP as the IdP. Deploys six
`ConfluentRolebinding` CRs: `platform-admin` (SystemAdmin), `topic-admin` (ResourceOwner
PREFIXED), `producer-only` (DeveloperWrite), `consumer-only` (DeveloperRead),
`schema-admin` (ResourceOwner Subject PREFIXED), `auditor-readonly` (DeveloperRead on
`_confluent-audit-log-events` and SR subjects ONLY — not on `payments.*`).

All bindings use LDAP groups, not individuals.

### Layer 02: mTLS + FIPS

**Why:** `autoGeneratedCerts` provides no CA trust chain and no client authentication.
GLBA, PCI-DSS 4.x § 4.2.1, and FFIEC require encryption-in-transit and mutual auth.
TLS 1.0/1.1 explicitly prohibited.

**What:** Replaces `autoGeneratedCerts` with named `secretRef` PEM Secrets. Enables
`listeners.internal.authentication.type: mtls`. Sets `spec.tls.fips.enabled: true`
(requires OCP FIPS-at-install — see `KNOWN-GAPS.md`). Pins `TLSv1.3,TLSv1.2` and
FIPS-approved cipher suites. Deploys cert-manager `ClusterIssuer` and `Certificate` CRs
for auto-rotation (s390x-supported, FIPS-validated since cert-manager ≥1.14.0).

### Layer 03: Schema Registry governance

**Why:** Default SR compatibility is `BACKWARD` — allows schema changes that break older
consumers. SEC/FINRA require regulatory replay across any schema version window.
Hard delete (`?permanent=true`) is irreversible.

**What:** Sets `schema.compatibility.level=full_transitive` via `configOverrides.server`.
Deploys an idempotent `restartPolicy: Never` bootstrap Job that PUTs FULL_TRANSITIVE
to the SR REST API (the one sanctioned explicit step). Hard-delete restriction is
enforced via `ResourceOwner` RBAC scoping from layer 01.

### Layer 04: Audit logging

**Why:** Without audit logging, there is no forensic record of access. OFAC/AML/SOX
require 7-year immutable audit trails. No logging = automatic finding in bank exams.

**What:** Sets `confluent.security.event.router.config` on the Kafka CR to route
authn/authz/management events to `_confluent-audit-log-events`. Pre-creates the topic
with `retention.ms=220752000000` (7y) in prod, 30d in dev. Re-enables Connect
(upstream had it commented out) with Splunk Sink (HEC) and HTTP Sink → Dynatrace
connectors. SIEM dashboards: `observability/splunk/`, `observability/dynatrace/`.

## Build and validation

### Prerequisites

- RHOCP 4.14+ cluster on IBM LinuxONE (s390x workers, FIPS mode at install)
- `flox` CLI installed on your workstation (macOS or Linux/x86)

### Build

```bash
# 1. Activate the Flox dev environment — installs tools + fetches upstream
cd accelerators/confluent-on-linuxone
flox activate

# 2. Dry-run against the cluster (exercises CFK CRD admission)
kustomize build overlays/prod | oc apply --dry-run=server -f - -n confluent

# 3. Apply
kustomize build overlays/prod | oc apply -f - -n confluent
```

### Validate each layer

```bash
# Layer 01: RBAC — asserts role bindings, producer-only cannot consume, D-02 scope
bash layers/01-rbac/validate-rbac.sh

# Layer 02: mTLS — asserts no-cert rejected, valid-cert succeeds, TLS 1.0 rejected
bash layers/02-tls/validate-mtls.sh

# Layer 03: Schema governance — asserts FULL_TRANSITIVE, incompatible change rejected
bash layers/03-schema-governance/validate-schema-governance.sh

# Layer 04: Audit — asserts KafkaTopic exists, Connect RUNNING, audit topic populated
bash layers/04-audit/validate-audit.sh
```

Cluster-dependent — requires OCP access. Not run in CI (see `.github/workflows/accelerator-linuxone.yml`).
