From modules/topic/main.tf (RBAC pattern):
```hcl
# Producers get DeveloperWrite on Topic + DeveloperWrite on Subject (value+key)
# Consumers get DeveloperRead on Topic + DeveloperRead on Subject + DeveloperRead on Group (PREFIXED)
# Group pattern: {principal-name}-* with PREFIXED patternType
# Subject names: {topic_name}-value, {topic_name}-key
```

MDS REST API endpoints:
- GET  /security/1.0/authenticate (Basic Auth) -> {auth_token, token_type, expires_in}
- POST /security/1.0/principals/{principal}/roles/{role}/bindings -> 204 (create binding)
- DELETE /security/1.0/principals/{principal}/roles/{role}/bindings -> 204 (delete binding)
- POST /security/1.0/principals/{principal}/roles/{role}/resources -> 200 (list resources for principal+role)
- POST /security/1.0/lookup/principals/{principal}/roleNames -> 200 (list roles for principal)

Binding body format:
```json
{
  "scope": {"clusters": {"kafka-cluster": "cluster-id"}},
  "resourcePatterns": [{"resourceType": "Topic", "name": "topic-name", "patternType": "LITERAL"}]
}
```

Consumer group binding (PREFIXED):
```json
{"resourceType": "Group", "name": "sa-consumer-", "patternType": "PREFIXED"}
```

SR subject binding:
```json
{
  "scope": {"clusters": {"kafka-cluster": "cluster-id", "schema-registry-cluster": "schema-registry"}},
  "resourcePatterns": [{"resourceType": "Subject", "name": "topic-name-value", "patternType": "LITERAL"}]
}
```

    ```yaml
    cp_mds_url: ""                          # MDS REST API URL, e.g., https://broker-host:8090

    cp_rbac_reconcile: true                 # Enable stale binding removal (ARBAC-05)
    cp_rbac_token_refresh_margin: 60        # Seconds before expiry to refresh token
    cp_rbac_results:                        # Output variable for downstream orchestration
      created: 0
      removed: 0
      unchanged: 0
      failed: 0
      errors: []
    ```

    The `cp_rbac_bindings` list format (each item):
    ```yaml
    cp_rbac_bindings:
      - topic_name: corebanking.transactions.v1.account-transaction
        producers:
          - User:sa-corebanking-producer
        consumers:
          - User:sa-corebanking-consumer
          - User:sa-fraud-enrichment
    ```

    All credential variables default to empty string. Variable names use snake_case per ansible-lint.

    **meta/main.yml** -- Role metadata:
    ```yaml
    galaxy_info:
      role_name: cp_rbac
      author: fsi-c4e
    ```

    **tasks/main.yml** -- Role entry point. Must:
    1. Acquire MDS token: include `authenticate.yml`.
    2. If `ansible_check_mode`, include `check.yml` and skip mutations.
    3. Otherwise, loop over `cp_rbac_bindings`. For each binding item:
       a. Include `topic_bindings.yml` to create per-topic producer/consumer bindings.
       b. Include `group_bindings.yml` to create consumer group PREFIXED bindings.
       c. Include `sr_bindings.yml` to create Schema Registry subject bindings.
       d. Before each include block, check token expiry and re-authenticate if needed: `ansible.builtin.include_tasks: authenticate.yml` when `ansible_date_time.epoch | int >= (_mds_token_expires_at | int)`.
    4. If `cp_rbac_reconcile` is true, include `reconcile.yml` to detect and remove stale bindings.
    5. Use `ignore_errors: true` on per-binding includes and collect errors at end (locked decision).
    6. Register `cp_rbac_results` with created/removed/unchanged/failed/errors counts.
    7. Fail with summary if `cp_rbac_results.failed | int > 0`.

    **tasks/authenticate.yml** -- MDS token acquisition. Must:
    1. GET `{{ cp_mds_url }}/security/1.0/authenticate` with `url_username: "{{ cp_mds_username }}"`, `url_password: "{{ cp_mds_password }}"`, `force_basic_auth: true`, `return_content: true`, `status_code: [200]`.
    2. Use `no_log: true` on this task (credentials in URL).
    3. Use `retries: 3`, `delay: 5` for transient errors.
    4. Register `_mds_auth_response`.
    5. Set facts:
       - `_mds_token: "{{ _mds_auth_response.json.auth_token }}"` (with `no_log: true`)
       - `_mds_token_expires_at: "{{ ansible_date_time.epoch | int + _mds_auth_response.json.expires_in | int - cp_rbac_token_refresh_margin | int }}"` -- compute absolute epoch when token should be refreshed (actual TTL from response minus safety margin, per research: do NOT hardcode 15 minutes).

    **tasks/topic_bindings.yml** -- Per-topic producer/consumer bindings. Receives `binding_item` loop var. Must:
    1. For each principal in `binding_item.producers`:
       POST `{{ cp_mds_url }}/security/1.0/principals/{{ principal }}/roles/DeveloperWrite/bindings` with body:
       ```json
       {
         "scope": {"clusters": {"kafka-cluster": "{{ cp_kafka_cluster_id }}"}},
         "resourcePatterns": [{"resourceType": "Topic", "name": "{{ binding_item.topic_name }}", "patternType": "LITERAL"}]
       }
       ```
       Headers: `Authorization: "Bearer {{ _mds_token }}"`, `Content-Type: "application/json"`. Status codes: [204]. Use `retries: 3`, `delay: 5`.
    2. For each principal in `binding_item.consumers`:
       POST `{{ cp_mds_url }}/security/1.0/principals/{{ principal }}/roles/DeveloperRead/bindings` with same body structure but `DeveloperRead` role.
    3. MDS POST to create binding is idempotent -- creating an already-existing binding returns 204 (no error). Use `changed_when` based on whether the binding was actually new (track via a pre-check GET or assume changed for simplicity since MDS is idempotent).

    **tasks/group_bindings.yml** -- Consumer group PREFIXED bindings. Receives `binding_item` loop var. Must:
    1. For each principal in `binding_item.consumers`:
       - Extract the principal name (strip `User:` prefix to get e.g., `sa-corebanking-consumer`).
       - POST `{{ cp_mds_url }}/security/1.0/principals/{{ principal }}/roles/DeveloperRead/bindings` with body:
         ```json
         {
           "scope": {"clusters": {"kafka-cluster": "{{ cp_kafka_cluster_id }}"}},
           "resourcePatterns": [{"resourceType": "Group", "name": "{{ principal_name }}-", "patternType": "PREFIXED"}]
         }
         ```
         Note: Use `PREFIXED` patternType, NOT `LITERAL`. The group name pattern is `{principal_name}-` (WITHOUT the asterisk -- MDS handles prefix matching implicitly per research pitfall 6).
    2. Status codes: [204]. Use `retries: 3`, `delay: 5`.

    **tasks/sr_bindings.yml** -- Schema Registry subject bindings. Receives `binding_item` loop var. Must:
    1. Derive subject names: `{{ binding_item.topic_name }}-value` and `{{ binding_item.topic_name }}-key` (TopicNameStrategy, matching Terraform local `value_subject` and `key_subject` from modules/topic/main.tf).
    2. For each producer principal: POST DeveloperWrite binding for BOTH value and key subjects:
       ```json
       {
         "scope": {"clusters": {"kafka-cluster": "{{ cp_kafka_cluster_id }}", "schema-registry-cluster": "{{ cp_sr_cluster_id }}"}},
         "resourcePatterns": [{"resourceType": "Subject", "name": "{{ binding_item.topic_name }}-value", "patternType": "LITERAL"}]
       }
       ```
       Then the same for `-key` subject.
    3. For each consumer principal: POST DeveloperRead binding for both value and key subjects (same scope and resourcePatterns, but DeveloperRead role).
    4. Status codes: [204]. Use `retries: 3`, `delay: 5`.

    **tasks/reconcile.yml** -- LIST/DIFF/ADD/REMOVE stale binding cleanup. Must:
    1. Build the "desired state" -- a set of all (principal, role, resourceType, name, patternType) tuples from `cp_rbac_bindings`.
    2. For each unique principal in the desired state, LIST current bindings:
       POST `{{ cp_mds_url }}/security/1.0/principals/{{ principal }}/roles/DeveloperWrite/resources` with scope body to get current DeveloperWrite resources.
       POST `{{ cp_mds_url }}/security/1.0/principals/{{ principal }}/roles/DeveloperRead/resources` with scope body to get current DeveloperRead resources.
    3. Compute stale bindings: current bindings that are NOT in the desired state. Filter to only Topic, Group, and Subject resourceTypes (don't touch Cluster-level bindings).
    4. For each stale binding, DELETE:
       DELETE `{{ cp_mds_url }}/security/1.0/principals/{{ principal }}/roles/{{ role }}/bindings` with the scope and resourcePatterns body matching the stale binding.
    5. Track removed count in results.
    6. Use `ignore_errors: true` per deletion and collect errors.

    **tasks/check.yml** -- Check-mode binding diff report. Must:
    1. Use `check_mode: false` on all uri tasks to force execution in check mode.
    2. Include `authenticate.yml` to get a valid token (GET is read-only).
    3. For each binding in `cp_rbac_bindings`, query current state via resources listing.
    4. Compute diff: bindings to ADD, bindings to REMOVE (if reconcile enabled).
    5. Report planned changes via `ansible.builtin.debug` with `msg` describing what WOULD happen.
    6. Use `changed_when` to signal whether changes are planned.

    All task files MUST use FQCN. Use `no_log: true` on any task handling credentials or tokens.
