    **GREEN phase -- Implement the playbook and template (commit as feat):**

    **ansible/playbooks/dr-drill.yml:** Multi-play playbook with 5 plays:

    ```yaml
    ---
    # ===========================================================================
    # FSI Kafka Platform -- DR Drill Playbook
    # ===========================================================================
    # Orchestrates a full DR drill cycle for quarterly compliance testing:
    #   1. Pre-drill state snapshot
    #   2. Failover via selected DR backend (cp_dr_mrc or cp_dr_mm2)
    #   3. Post-failover validation
    #   4. Failback via selected DR backend
    #   5. Post-failback validation and compliance report generation
    #
    # Usage:
    #   ansible-playbook dr-drill.yml                          # MRC backend (default)
    #   ansible-playbook dr-drill.yml -e dr_drill_backend=cp_dr_mm2  # MM2 backend
    #   ansible-playbook dr-drill.yml --check                  # Dry-run audit
    #
    # Variables:
    #   dr_drill_backend: cp_dr_mrc (default) or cp_dr_mm2
    #   dr_drill_report_dir: /tmp (default) -- output directory for report
    # ===========================================================================
    ```

    Play 1 - Pre-drill state snapshot:
    - hosts: kafka_broker[0], gather_facts: true
    - Tasks: Set `_drill_id` (UUID-like from `ansible_date_time.epoch`), `_drill_start` (iso8601), `_drill_steps` (empty list), `_drill_all_passed` (true)

    Play 2 - Failover:
    - hosts: kafka_broker[0], gather_facts: false
    - Tasks:
      - Record step start timestamp
      - Include role `{{ dr_drill_backend | default('cp_dr_mrc') }}` with operation: failover
      - Capture results: `_failover_results` from `cp_dr_mrc_results` when backend is cp_dr_mrc, or `cp_dr_mm2_results` when backend is cp_dr_mm2. Use a set_fact that reads the appropriate variable based on backend: `"{{ lookup('vars', dr_drill_backend | default('cp_dr_mrc') ~ '_results') }}"`
      - Record step end timestamp and append step to `_drill_steps` list: `{number: 1, name: "Failover execution", start: ..., end: ..., duration: ..., result: PASS/FAIL}`
      - Update `_drill_all_passed` if validation_passed is false

    Play 3 - Post-failover validation pause:
    - hosts: kafka_broker[0], gather_facts: false
    - Tasks: Record validation step in _drill_steps (step 2)

    Play 4 - Failback:
    - hosts: kafka_broker[0], gather_facts: false
    - Tasks:
      - Record step start timestamp
      - Include role `{{ dr_drill_backend | default('cp_dr_mrc') }}` with operation: failback
      - Capture results: `_failback_results`
      - Record step end and append to `_drill_steps` (step 3)
      - Update `_drill_all_passed`

    Play 5 - Generate compliance report:
    - hosts: kafka_broker[0], gather_facts: true
    - Tasks:
      - Record `_drill_end` timestamp
      - Calculate `_drill_duration_seconds` (epoch diff)
      - Render template `ansible/templates/dr-drill-report.md.j2` to `{{ dr_drill_report_dir | default('/tmp') }}/dr-drill-{{ ansible_date_time.date }}.md`
      - Display report path via debug
      - Display overall verdict via debug

    Note on variable scope: All plays use `hosts: kafka_broker[0]`, so set_fact values persist across plays on the same host without needing fact caching.

    IMPORTANT: All module references use FQCN. All task names start with uppercase. Template src path uses `../../templates/dr-drill-report.md.j2` relative to playbooks/ or absolute `{{ playbook_dir }}/../templates/dr-drill-report.md.j2`.

    **ansible/templates/dr-drill-report.md.j2:** Jinja2 template based on research Pattern 4:

    ```markdown
    # DR Drill Compliance Report

    **Drill ID:** {{ _drill_id }}
    **Date:** {{ _drill_start }}
    **Completed:** {{ _drill_end }}
    **Duration:** {{ _drill_duration_seconds }}s
    **Environment:** {{ inventory_hostname }}
    **DR Backend:** {{ dr_drill_backend | default('cp_dr_mrc') }}
    **Overall Verdict:** {{ 'PASS' if _drill_all_passed else 'FAIL' }}

    ---

    ## Executive Summary

    A full disaster recovery drill was executed on {{ _drill_start | regex_replace('T.*', '') }}.
    The drill exercised {{ dr_drill_backend | default('cp_dr_mrc') }} failover
    and failback with state validation at each step.

    **Result: {{ 'ALL STEPS PASSED' if _drill_all_passed else 'ONE OR MORE STEPS FAILED' }}**

    ## Drill Steps

    | # | Step | Start | End | Duration | Result |
    |---|------|-------|-----|----------|--------|
    {% for step in _drill_steps %}
    | {{ step.number }} | {{ step.name }} | {{ step.start }} | {{ step.end }} | {{ step.duration }}s | {{ step.result }} |
    {% endfor %}

    ## Validation Details

    ### Post-Failover
    - Election triggered: {{ _failover_results.election_triggered | default(_failover_results.connectors_paused | default('N/A')) }}
    - Consul region flipped: {{ _failover_results.consul_flipped | default('N/A') }}
    - Validation passed: {{ _failover_results.validation_passed | default('N/A') }}

    ### Post-Failback
    - Election triggered: {{ _failback_results.election_triggered | default(_failback_results.connectors_resumed | default('N/A')) }}
    - Consul region flipped: {{ _failback_results.consul_flipped | default('N/A') }}
    - Validation passed: {{ _failback_results.validation_passed | default('N/A') }}

    ## Regulatory Attestation

    This report certifies that a full DR failover/failback cycle was executed
    and validated on the above date. This evidence supports quarterly DR
    testing requirements per OCC SR 20-13, FDIC FIL-67-2006, and internal
    BCM policy.

    **Prepared by:** Automated DR Drill Playbook (ansible)
    **Report generated:** {{ ansible_date_time.iso8601 }}
    ```

    The template must handle both MRC results (election_triggered, election_type) and MM2 results (connectors_paused, connectors_resumed) gracefully using Jinja default filters.
