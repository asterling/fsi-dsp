**In `modules/topic/variables.tf`:**
1. Add `create_service_accounts` variable:
   ```hcl
   variable "create_service_accounts" {
     description = "Whether to create new service accounts or use existing IDs from producer/consumer_service_accounts"
     type        = bool
     default     = false
   }
   ```
2. Add `producer_sa_names` variable:
   ```hcl
   variable "producer_sa_names" {
     description = "Display names for producer SAs to create (used when create_service_accounts = true)"
     type        = list(string)
     default     = []
   }
   ```
3. Add `consumer_sa_names` variable:
   ```hcl
   variable "consumer_sa_names" {
     description = "Display names for consumer SAs to create (used when create_service_accounts = true)"
     type        = list(string)
     default     = []
   }
   ```
4. Update `producer_service_accounts` validation to be conditional -- only require length > 0 when `create_service_accounts = false`. When `create_service_accounts = true`, producer_sa_names is the source. Change the validation to:
   ```hcl
   validation {
     condition     = var.create_service_accounts || length(var.producer_service_accounts) > 0
     error_message = "At least one producer service account ID is required when create_service_accounts is false."
   }
   ```
   NOTE: The Terraform variable validation block cannot reference other variables directly. Instead, remove the validation from the variable block and add a `check` block or a `precondition` in the locals, OR use a simpler approach: keep `producer_service_accounts` with `default = []` and validate via a `locals` null_resource precondition. Actually, the simplest Terraform-compatible approach is to relax the validation on `producer_service_accounts` to allow empty list (since SA names will be used instead), and add a validation `precondition` on the topic resource:
   ```hcl
   variable "producer_service_accounts" {
     description = "List of Confluent Cloud service account IDs that produce to this topic (used when create_service_accounts = false)"
     type        = list(string)
     default     = []
   }
   ```
   Then add a lifecycle precondition on `confluent_kafka_topic.this`:
   ```hcl
   lifecycle {
     prevent_destroy = true
     precondition {
       condition     = length(local.effective_producer_sa_ids) > 0
       error_message = "At least one producer SA is required. Set producer_service_accounts (reference mode) or producer_sa_names + create_service_accounts = true (create mode)."
     }
   }
   ```

**In `modules/topic/main.tf`:**
1. After the existing `locals` block, add SA creation resources (place BEFORE the RBAC bindings section):
   ```hcl
   # ---------------------------------------------------------------------------
   # Service Accounts — Conditional creation (per D-01, D-02)
   # ---------------------------------------------------------------------------
   resource "confluent_service_account" "producer" {
     for_each     = var.create_service_accounts ? toset(var.producer_sa_names) : toset([])
     display_name = each.value
     description  = "Producer SA for topic ${local.topic_name}"
   }

   resource "confluent_service_account" "consumer" {
     for_each     = var.create_service_accounts ? toset(var.consumer_sa_names) : toset([])
     display_name = each.value
     description  = "Consumer SA for topic ${local.topic_name}"
   }
   ```
2. Add effective SA ID locals (inside the existing `locals` block or a new one):
   ```hcl
   locals {
     # Resolve effective SA IDs: created IDs when create mode, provided IDs when reference mode
     effective_producer_sa_ids = var.create_service_accounts ? [
       for sa in confluent_service_account.producer : sa.id
     ] : var.producer_service_accounts

     effective_consumer_sa_ids = var.create_service_accounts ? [
       for sa in confluent_service_account.consumer : sa.id
     ] : var.consumer_service_accounts
   }
   ```
3. Refactor ALL existing RBAC bindings to use `local.effective_producer_sa_ids` and `local.effective_consumer_sa_ids` instead of `var.producer_service_accounts` and `var.consumer_service_accounts`:
   - `confluent_role_binding.producer`: `for_each = toset(local.effective_producer_sa_ids)`
   - `confluent_role_binding.consumer`: `for_each = toset(local.effective_consumer_sa_ids)`
   - `confluent_role_binding.consumer_group`: `for_each = toset(local.effective_consumer_sa_ids)`
   - `confluent_role_binding.sr_read`: `for_each = toset(concat(local.effective_producer_sa_ids, local.effective_consumer_sa_ids))`
   - `confluent_role_binding.sr_write`: `for_each = toset(local.effective_producer_sa_ids)`
4. Add lifecycle precondition on `confluent_kafka_topic.this` to validate at least one producer SA exists.
