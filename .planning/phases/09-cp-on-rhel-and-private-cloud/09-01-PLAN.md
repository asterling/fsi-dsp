**CP-RHEL Ansible Scenario (scenarios/cp-rhel/):**

1. **README.md** -- Follow the pattern from scenarios/cfk-openshift/README.md. Include:
   - Title: "CP on RHEL -- Confluent Platform on Bare-Metal RHEL"
   - Description: cp-ansible-based deployment of Kafka, Schema Registry, Connect, MDS RBAC on RHEL 8+
   - Prerequisites: RHEL 8.x or 9.x, Ansible 9.x (core 2.16+), Java 17 JDK, cp-ansible 7.6.x collection
   - Quick Start: 4 steps -- (1) Install cp-ansible collection (`ansible-galaxy collection install confluent.platform`), (2) Copy and customize inventory (`cp inventory/hosts.yml.example inventory/hosts.yml`), (3) Set secrets in vault/vars, (4) Run playbook (`ansible-playbook -i inventory/hosts.yml playbooks/deploy-cp.yml`)
   - Architecture section: 3 brokers (east DC, multi-rack), 2 SR nodes, 2 Connect workers, MDS for RBAC
   - Topic governance: CPTopic YAML format validated by c4e-precheck.py
   - Security: TLS enabled (mutual auth), MDS RBAC, FIPS toggle (fips_enabled: false by default, see validate-fips.yml)
   - Note: Standalone Flink and FIPS validation covered in separate plan

2. **inventory/hosts.yml.example** -- Ansible inventory template:
   ```yaml
   all:
     vars:
       confluent_server_enabled: true
       confluent_package_version: "7.6.0"
     children:
       kafka_broker:
         hosts:
           kafka-east-1: {broker_id: 1, kafka_broker_custom_properties: {broker.rack: us-east-1a}}
           kafka-east-2: {broker_id: 2, kafka_broker_custom_properties: {broker.rack: us-east-1b}}
           kafka-east-3: {broker_id: 3, kafka_broker_custom_properties: {broker.rack: us-east-1c}}
       schema_registry:
         hosts:
           sr-east-1: {}
           sr-east-2: {}
       kafka_connect:
         hosts:
           connect-east-1: {}
           connect-east-2: {}
   ```

3. **inventory/group_vars/all.yml** -- Common variables:
   ```yaml
   # CP version and base settings
   confluent_server_enabled: true
   confluent_package_version: "7.6.0"

   # TLS -- mutual auth enabled
   ssl_enabled: true
   ssl_mutual_auth_enabled: true

   # MDS RBAC
   rbac_enabled: true
   mds_super_user: mds
   mds_super_user_password: "{{ vault_mds_password }}"
   kafka_broker_ldap_user: kafka_broker
   kafka_broker_ldap_password: "{{ vault_kafka_broker_password }}"
   schema_registry_ldap_user: schema_registry
   schema_registry_ldap_password: "{{ vault_sr_password }}"
   kafka_connect_ldap_user: connect_worker
   kafka_connect_ldap_password: "{{ vault_connect_password }}"

   # FIPS -- toggle for FIPS 140-2 compliance (see validate-fips.yml)
   fips_enabled: false
   fips_mode: "fips-140-2"

   # JMX exporter for observability
   jmxexporter_enabled: true
   ```

4. **inventory/group_vars/kafka_broker.yml** -- Broker-specific config:
   ```yaml
   kafka_broker_custom_properties:
     # MRC replica placement -- enable for multi-region deployments
     # confluent.tier.feature: "true"
     # confluent.tier.backend: "S3"  # or "GCS" / "ABS"

     # Confluent Server license
     confluent.license.topic.replication.factor: 3

     # Default replication for internal topics
     confluent.balancer.topic.replication.factor: 3

     # Log retention defaults (overridden per-topic via CPTopic definitions)
     log.retention.hours: 168

     # Producer acks enforcement for RPO guarantees
     # min.insync.replicas set per-topic via CPTopic definition
   ```

5. **inventory/group_vars/schema_registry.yml** -- SR config:
   ```yaml
   schema_registry_custom_properties:
     schema.compatibility.level: BACKWARD
     # kafkastore.topic.replication.factor inherits from cp-ansible defaults (3)
   ```

6. **inventory/group_vars/kafka_connect.yml** -- Connect config:
   ```yaml
   kafka_connect_custom_properties:
     # Distributed mode defaults
     config.storage.replication.factor: 3
     offset.storage.replication.factor: 3
     status.storage.replication.factor: 3

     # Plugin path for JDBC and custom connectors
     plugin.path: "/usr/share/java,/usr/share/confluent-hub-components"
   ```

7. **playbooks/deploy-cp.yml** -- Main deployment playbook:
   ```yaml
   ---
   # Deploy Confluent Platform on RHEL via cp-ansible roles
   # Usage: ansible-playbook -i inventory/hosts.yml playbooks/deploy-cp.yml
   - name: Deploy Confluent Platform
     hosts: all
     gather_facts: true
     collections:
       - confluent.platform
     roles:
       - role: kafka_broker
         when: "'kafka_broker' in group_names"
       - role: schema_registry
         when: "'schema_registry' in group_names"
       - role: kafka_connect
         when: "'kafka_connect' in group_names"
   ```

8. **topics/ directory** -- Three CPTopic YAML files matching the CFK examples but with `kind: CPTopic` format. Each file has:
   ```yaml
   # scenarios/cp-rhel/topics/corebanking-account-txn.yml
   kind: CPTopic
   metadata:
     name: corebanking.core.v1.account-transaction
     labels:
       fsi.sla-tier: critical
       fsi.owner: corebanking-team@fsi.org
       fsi.data-classification: confidential
       fsi.domain: corebanking
       fsi.application: core
       fsi.version: v1
       fsi.entity: account-transaction
   spec:
     partitionCount: 12
     replicationFactor: 5
     configs:
       retention.ms: "604800000"
       min.insync.replicas: "3"
     replicaPlacement: mrc-placement-critical.json
   ```
