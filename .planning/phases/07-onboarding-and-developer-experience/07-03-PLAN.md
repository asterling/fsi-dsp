**Script header** (match roundtrip-test.sh style):
```bash
#!/usr/bin/env bash
# =============================================================================
# FSI Kafka Platform -- Error Path Integration Tests
# =============================================================================
# Validates failure handling: serialization, RBAC denial, schema incompat, broker failure
# Run against local-dev Docker Compose (requires services running).
#
# Prerequisites:
#   cd reference/local-dev && docker compose up -d
#   # Wait for all services to be healthy
#
# Usage:
#   ./error-path-tests.sh [bootstrap_server] [sr_url]
# =============================================================================
set -euo pipefail
```

**Variables:**
```bash
BOOTSTRAP="${1:-localhost:9092}"
SR_URL="${2:-http://localhost:8081}"
TOPIC="test.errorpath.v1.validation"
DLQ_TOPIC="test.errorpath.v1.validation.dlq"
PASSED=0
FAILED=0
```

**Helper functions:**
- `wait_for_broker()` -- Poll `docker exec fsi-broker kafka-broker-api-versions --bootstrap-server broker:29092` up to 30 times with 2s sleep. Exit 1 if never healthy.
- `cleanup()` -- Delete test topics, remove test ACLs. Called via trap on EXIT.
- `record_pass(test_name)` -- Increment PASSED, echo "  PASS -- ${test_name}"
- `record_fail(test_name, detail)` -- Increment FAILED, echo "  FAIL -- ${test_name}: ${detail}"

**Setup section:**
```bash
echo "=== FSI Error Path Integration Tests ==="
echo "Bootstrap: ${BOOTSTRAP}"
echo "SR:        ${SR_URL}"
echo ""

# Create test topic and DLQ topic
echo "[SETUP] Creating test topics..."
docker exec fsi-broker kafka-topics --create \
  --topic "${TOPIC}" --partitions 1 --replication-factor 1 \
  --bootstrap-server broker:29092 --if-not-exists 2>/dev/null || true
docker exec fsi-broker kafka-topics --create \
  --topic "${DLQ_TOPIC}" --partitions 1 --replication-factor 1 \
  --bootstrap-server broker:29092 --if-not-exists 2>/dev/null || true
```

Register a valid test schema (same as roundtrip-test.sh pattern):
```bash
SCHEMA='{"type":"record","name":"ErrorPathTest","namespace":"org.fsi.test","fields":[{"name":"test_key","type":"string"},{"name":"test_value","type":"string"},{"name":"timestamp","type":{"type":"long","logicalType":"timestamp-millis"}}]}'
```

**Error Path 1: Serialization Failure** `[1/4]`
- Send JSON that does NOT match the registered Avro schema (e.g., `{"unknown_field": 123}`) via `kafka-avro-console-producer`
- The console producer should output an error about serialization/schema mismatch
- Capture stderr, grep for "Error" or "SerializationException" or "Could not"
- PASS if error detected, FAIL if message was accepted without error

**Error Path 2: RBAC Denial** `[2/4]`
- Enable ACL authorizer on the broker: `docker exec fsi-broker kafka-configs --bootstrap-server broker:29092 --alter --entity-type brokers --entity-default --add-config authorizer.class.name=kafka.security.authorizer.AclAuthorizer,super.users=User:ANONYMOUS`
  - Note: Since local dev uses PLAINTEXT, all clients authenticate as "ANONYMOUS". Set ANONYMOUS as super user first so existing connections don't break.
- Create a deny ACL for a test principal: `docker exec fsi-broker kafka-acls --bootstrap-server broker:29092 --add --deny-principal User:denied-user --operation Write --topic ${TOPIC}`
- Attempt to produce as "denied-user" -- this is tricky in PLAINTEXT mode, so instead:
  - Alternative approach: Add a deny ACL for User:ANONYMOUS on a separate test topic `test.errorpath.v1.rbac-denied`, then try to produce to that topic
  - `docker exec fsi-broker kafka-topics --create --topic test.errorpath.v1.rbac-denied --partitions 1 --replication-factor 1 --bootstrap-server broker:29092 --if-not-exists 2>/dev/null || true`
  - `docker exec fsi-broker kafka-acls --bootstrap-server broker:29092 --add --deny-principal User:ANONYMOUS --operation Write --topic test.errorpath.v1.rbac-denied`
  - Attempt produce via console-producer to test.errorpath.v1.rbac-denied
  - Capture output, grep for "TopicAuthorizationException" or "TOPIC_AUTHORIZATION_FAILED" or "Not authorized"
  - PASS if authorization error detected
- Cleanup: Remove ACL (`--remove --deny-principal User:ANONYMOUS`), remove ACL authorizer config (`--delete-config authorizer.class.name,super.users`)

**Error Path 3: Schema Incompatibility** `[3/4]`
- Register initial schema with FULL compatibility on the subject
- Set subject compatibility to FULL: `curl -s -X PUT "${SR_URL}/config/${TOPIC}-value" -H "Content-Type: application/vnd.schemaregistry.v1+json" -d '{"compatibility":"FULL"}'`
- Attempt to register an incompatible schema evolution (remove a required field, add required field without default):
  ```json
  {"type":"record","name":"ErrorPathTest","namespace":"org.fsi.test","fields":[{"name":"test_key","type":"string"},{"name":"breaking_new_field","type":"string"}]}
  ```
- Capture response, check for `is_compatible: false` or HTTP 409
- PASS if incompatibility detected, FAIL if schema was accepted

**Error Path 4: Broker Failure** `[4/4]`
- Produce a message successfully first (confirm baseline)
- Stop the broker: `docker compose -f reference/local-dev/docker-compose.yml stop broker`
- Attempt to produce -- should fail with timeout or broker unavailable (use `timeout 15` to prevent hanging)
- Capture error output
- Restart broker: `docker compose -f reference/local-dev/docker-compose.yml start broker`
- Wait for broker recovery: call `wait_for_broker()`
- Produce another message successfully (confirm recovery)
- PASS if: initial produce worked, produce during outage failed, post-recovery produce worked

**Summary section:**
```bash
echo ""
echo "=== ERROR PATH TEST RESULTS ==="
echo "  Passed: ${PASSED}/4"
echo "  Failed: ${FAILED}/4"

if [ "${FAILED}" -gt 0 ]; then
  echo ""
  echo "RESULT: ${FAILED} ERROR PATH TESTS FAILED"
  exit 1
fi
echo ""
echo "RESULT: ALL ERROR PATH TESTS PASSED"
```

**Cleanup via trap:**
```bash
trap cleanup EXIT
```

**Part A: Custom Flink Dockerfile** (`reference/local-dev/flink-sql/Dockerfile`)

Create the directory `reference/local-dev/flink-sql/` and add a Dockerfile:

```dockerfile
# =============================================================================
# FSI Kafka Platform -- Flink SQL Local Dev Image
# =============================================================================
# Custom Flink image with Kafka and Avro-Confluent connector JARs pre-installed.
# Based on Apache Flink 1.20 (last stable 1.x release).
#
# Connector versions:
#   - flink-sql-connector-kafka: 3.2.0-1.20
#     Chosen for Kafka 3.6/7.6 protocol compatibility. The 3.4.0-1.20 version
#     targets a newer Kafka client that may introduce protocol negotiation issues
#     with Confluent Platform 7.6.0 (which bundles Kafka 3.6.x). Using 3.2.0-1.20
#     ensures the embedded Kafka client aligns with our broker version.
#   - flink-sql-avro-confluent: 1.20.0 (Avro + Confluent Schema Registry format)
# =============================================================================
FROM flink:1.20-java17

# Download Kafka SQL connector and Avro-Confluent format JARs from Maven Central
# These enable: CREATE TABLE ... WITH ('connector' = 'kafka', 'format' = 'avro-confluent')
RUN wget -q -P /opt/flink/lib/ \
    https://repo1.maven.org/maven2/org/apache/flink/flink-sql-connector-kafka/3.2.0-1.20/flink-sql-connector-kafka-3.2.0-1.20.jar && \
    wget -q -P /opt/flink/lib/ \
    https://repo1.maven.org/maven2/org/apache/flink/flink-sql-avro-confluent/1.20.0/flink-sql-avro-confluent-1.20.0.jar

# Verify JARs were downloaded
RUN ls -la /opt/flink/lib/flink-sql-connector-kafka-*.jar /opt/flink/lib/flink-sql-avro-confluent-*.jar
```

**Part B: Docker Compose Flink Services**

Append the following services to the existing `reference/local-dev/docker-compose.yml` AFTER the `connect` service. These use Docker Compose profiles so they are opt-in (existing `docker compose up -d` behavior unchanged).

```yaml

  # -- Flink (optional -- use --profile flink) --
  flink-jobmanager:
    build:
      context: ./flink-sql
      dockerfile: Dockerfile
    hostname: flink-jobmanager
    container_name: fsi-flink-jobmanager
    depends_on:
      broker:
        condition: service_healthy
      schema-registry:
        condition: service_healthy
    ports:
      - "8085:8081"
    environment:
      FLINK_PROPERTIES: |
        jobmanager.rpc.address: flink-jobmanager
        state.checkpoints.dir: file:///tmp/flink-checkpoints
        state.savepoints.dir: file:///tmp/flink-savepoints
        execution.checkpointing.interval: 60000
    command: jobmanager
    healthcheck:
      test: curl -f http://localhost:8081/overview || exit 1
      interval: 15s
      timeout: 10s
      retries: 5
      start_period: 30s
    profiles:
      - flink

  flink-taskmanager:
    build:
      context: ./flink-sql
      dockerfile: Dockerfile
    hostname: flink-taskmanager
    container_name: fsi-flink-taskmanager
    depends_on:
      flink-jobmanager:
        condition: service_healthy
    environment:
      FLINK_PROPERTIES: |
        jobmanager.rpc.address: flink-jobmanager
        taskmanager.numberOfTaskSlots: 4
        state.checkpoints.dir: file:///tmp/flink-checkpoints
        state.savepoints.dir: file:///tmp/flink-savepoints
    command: taskmanager
    profiles:
      - flink

  flink-sql-client:
    build:
      context: ./flink-sql
      dockerfile: Dockerfile
    hostname: flink-sql-client
    container_name: fsi-flink-sql-client
    depends_on:
      flink-jobmanager:
        condition: service_healthy
    environment:
      FLINK_PROPERTIES: |
        jobmanager.rpc.address: flink-jobmanager
        execution.target: remote
        rest.address: flink-jobmanager
        rest.port: 8081
    command: sleep infinity
    profiles:
      - flink
```
