**Part B: C4E Pre-Check Script** (per D-04)

Create `ci/scripts/c4e-precheck.py` — a Python script (stdlib only, matching existing validate-schemas.py pattern) that performs 5 validation categories:

**Arguments:**
- `--scenario-dir` (required): Path to scenario directory to validate
- `--schemas-dir` (default: "schemas/"): Path to schemas directory
- `--verbose`: Enable detailed output

**Check 1: Naming Validation**
- Parse all `.tf` files in `--scenario-dir` for `module` blocks that call `../../modules/topic`
- Extract `domain`, `application`, `schema_version`, `entity` arguments using regex: `(domain|application|schema_version|entity)\s*=\s*"([^"]*)"`
- Validate each against the same patterns as `modules/topic/variables.tf`:
  - domain: `^[a-z][a-z0-9-]{1,30}$`
  - application: `^[a-z][a-z0-9-]{1,30}$`
  - schema_version: `^v[0-9]+$`
  - entity: `^[a-z][a-z0-9-]{1,60}$`

**Check 2: Schema Compatibility**
- For each module block, if `schema_file` argument exists, resolve the `.avsc` path
- Call existing `validate_schema_structure()` and `validate_namespace()` logic (import from validate-schemas.py or duplicate the validation regex)
- Output PASS/FAIL per schema

**Check 3: RBAC Completeness**
- For each module block, check if `producer_service_accounts` or `producer_sa_names` is set (at least one must be non-empty)
- For modules with `data_classification = "confidential"`, verify `consumer_service_accounts` or `consumer_sa_names` is also set
- Output PASS/FAIL per module

**Check 4: SLA Tier Consistency**
- Parse `sla_tier` from each module block
- If `retention_ms_override` is set, verify it does not go below the tier minimum:
  - critical: 604800000 (7 days)
  - standard: 259200000 (3 days)
  - best-effort: 86400000 (1 day)
  - compliance: 220898482000 (7 years)
- If `partitions_override` is set, verify it is >= tier default (critical: 6, standard: 3, best-effort: 1, compliance: 3)

**Check 5: PII Field Audit**
- For each module with `data_classification = "confidential"`, verify `pii_fields` is set and non-empty
- If `schema_file` is referenced, load the .avsc and verify each listed PII field name appears in the schema's `fields` array

**Output format:**
```
=== C4E Pre-Check: {scenario-dir} ===
[CHECK 1/5] Naming Convention
  corebanking_account_txn: PASS (corebanking.transactions.v1.account-transaction)
  ...
[CHECK 2/5] Schema Compatibility
  ...
[CHECK 3/5] RBAC Completeness
  ...
[CHECK 4/5] SLA Tier Consistency
  ...
[CHECK 5/5] PII Field Audit
  ...

RESULT: {N} checks passed, {M} failed
```

Exit code 0 if all pass, 1 if any fail.

Add a new step to the `lint` job in `.github/workflows/terraform-scenario.yml`, placed AFTER the existing "Check Compatibility Overrides" step and BEFORE "Terraform Init". The step runs only in plan mode (PR validation).

**New step to add:**
```yaml
      - name: C4E Pre-Check Suite
        if: inputs.mode == 'plan'
        run: |
          echo "Running C4E pre-check suite..."
          python3 ci/scripts/c4e-precheck.py \
            --scenario-dir ${{ inputs.scenario-dir }} \
            --schemas-dir schemas/ \
            --verbose
```

This step:
- Runs only on PRs (`inputs.mode == 'plan'`) — not on apply
- Runs after schema validation and override checks (which are pre-existing)
- Runs before Terraform init/validate (catches issues before expensive Terraform operations)
- Does NOT have `continue-on-error: true` — C4E pre-check failures block the PR (per D-04: "human review is the final gate, not the first check")

Also add a conditional annotation step immediately after:
```yaml
      - name: C4E Pre-Check Annotation
        if: always() && inputs.mode == 'plan'
        run: |
          if [ $? -eq 0 ]; then
            echo "::notice title=C4E Pre-Check::All C4E pre-checks passed for ${{ inputs.scenario-dir }}"
          else
            echo "::warning title=C4E Pre-Check::C4E pre-check failures detected for ${{ inputs.scenario-dir }}. See step output for details."
          fi
```

Preserve all existing steps. Do not modify any other part of the workflow.
