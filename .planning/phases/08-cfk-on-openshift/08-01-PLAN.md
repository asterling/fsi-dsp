    Extend `ci/scripts/c4e-precheck.py` to parse and validate CFK KafkaTopic YAML files using the same governance rules as Terraform module validation. Per D-04: "CI pipeline validates naming/SLA/schema parity before merge (reusing existing Python validators from Phase 1)".

    **IMPORTANT:** The existing c4e-precheck uses Python stdlib only (no pip deps). For YAML parsing without PyYAML, implement a lightweight YAML parser that handles the limited subset used in KafkaTopic CRDs. The CRDs use simple key-value YAML that can be parsed with a line-by-line approach or by converting the well-structured YAML to JSON-equivalent extraction via regex. Alternatively, since KafkaTopic CRDs are simple structured YAML, use a minimal YAML-to-dict approach that handles the fields we need (metadata.name, metadata.labels, spec.partitionCount, spec.configs).

    **Add these functions to c4e-precheck.py:**

    1. `parse_yaml_simple(filepath)` -- Lightweight YAML parser for CFK CRDs:
       - Read file line by line
       - Track indentation to build nested dict
       - Handle: `key: value`, `key: "value"`, `key:` (start of nested block)
       - Return dict with structure matching YAML hierarchy
       - Only needs to handle the simple subset used in KafkaTopic CRDs (no arrays, no multiline strings, no anchors)

    2. `parse_cfk_topics(scenario_dir)` -- Find and parse KafkaTopic YAML files:
       - Look in `{scenario_dir}/topics/` directory
       - For each `.yaml`/`.yml` file, parse with `parse_yaml_simple()`
       - Filter for `kind: KafkaTopic` documents
       - Extract: metadata.name, metadata.labels (fsi.sla-tier, fsi.domain, fsi.owner, fsi.data-classification), spec.partitionCount, spec.replicas, spec.configs (retention.ms, cleanup.policy)
       - Return list of dicts with same structure as `parse_tf_modules` returns: `{'name': topic_name, 'file': filename, 'args': {'domain': ..., 'application': ..., ...}}`
       - Parse the topic name by splitting on dots: name parts = `{domain}.{application}.{version}.{entity}`

    3. **Modify `main()` function:**
       - After the existing `parse_tf_modules()` call, add: `cfk_modules = parse_cfk_topics(args.scenario_dir)`
       - Combine: `all_modules = modules + cfk_modules`
       - Pass `all_modules` to all 5 check functions instead of just `modules`
       - This way CFK topics get the exact same naming, schema, RBAC, SLA tier, and PII checks

    4. **CFK topic name to module args conversion** in `parse_cfk_topics`:
       - Split `metadata.name` on `.` to get [domain, application, version, entity]
       - If fewer than 4 parts, mark as parse error
       - Map labels to args: `fsi.sla-tier` -> `sla_tier`, `fsi.domain` -> `domain` (cross-check with name), `fsi.owner` -> `owner`, `fsi.data-classification` -> `data_classification`
       - Map spec.partitionCount -> `partitions_override` (only if not matching tier default)
       - Map spec.configs.retention.ms -> `retention_ms_override` (only if not matching tier default)
       - Set `schema_file` to empty string (CFK schemas registered separately)
       - Set producer/consumer SA lists to empty (ACLs managed separately for CFK)

    5. **Update `--scenario-dir` help text** to note it works with both Terraform and CFK YAML scenarios.
  </action>
