    - Args: Not used (MM2 failover pauses all MM2 connectors, not per-topic)
    - Per D-06: "stop MM2 connectors + flip Consul to DR. DR topics are already writable (no mirror promotion needed)."
    - local mm2_url="${FSI_MM2_CONNECT_URL:-${FSI_CONNECT_URL}}"

    - NOTE: mm2_failover_mirrors does NOT call flip_consul -- that's handled by the orchestrator (cmd_failover step sequence) just like CL backend

    - Wait for new connectors to reach RUNNING state
    - Print: "MM2 replication reversed (DR -> Primary). Monitor lag before cutover."
    - NOTE: Full failback sequence is orchestrated by cmd_failback. This function handles the MM2-specific mirror reversal step.

    - Parse task-level metrics from status response
    - Also query the source connector's assigned topics from config: `curl -s "${mm2_url}/connectors/${src}/config" | jq -r '.["topics"]'`
    - For each replicated topic, construct a lag entry
    - Return JSON array matching CL format: `[{"mirror_topic_name": "{alias}.{topic}", "mirror_lag_ms": N, "status": "ACTIVE|PAUSED|FAILED"}]`
