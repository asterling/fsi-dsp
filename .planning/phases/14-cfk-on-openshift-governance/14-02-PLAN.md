<objective>
Create the cfk_topic Ansible role that generates KafkaTopic CRDs from existing CPTopic YAML definitions with full governance parity to the cp_topic role. The key transformation: CPTopic integer configs become string-typed KafkaTopic CRD configs, SLA-tier defaults are derived from the same sla_tiers.yml, and topic names are validated with the same governance filter.

Purpose: Satisfy ACFK-03 -- ensuring identical governance outcomes regardless of whether topics are deployed via CP REST API (cp_topic) or CFK CRDs (cfk_topic).
Output: cfk_topic role, unit tests with governance parity assertions, updated CI matrix
</objective>

**3. Create ansible/roles/cfk_topic/tasks/main.yml** -- Entry point:
- Load shared governance vars: `ansible.builtin.include_vars` for `ansible/vars/sla_tiers.yml` and `ansible/vars/naming_rules.yml`
- Discover CPTopic files from `cfk_topics_dir` using `ansible.builtin.find` + `ansible.builtin.slurp` + `ansible.builtin.set_fact` pattern (COPY the exact discovery pattern from cp_topic/tasks/main.yml, adapted for `cfk_` variable prefix)
- Merge inline `cfk_topics` list with directory-discovered topics into `_cfk_all_topics`
- Route: when `ansible_check_mode` is true, include `check.yml`. Otherwise, loop over `_cfk_all_topics` including `validate.yml` then `generate.yml` per topic using `loop_control.loop_var: topic_item`
- IMPORTANT: Use the process-per-topic pattern. Include validate.yml and generate.yml sequentially for each topic_item. The cp_topic role uses process_one.yml as a dispatcher -- cfk_topic can use a similar pattern or inline the loop in main.yml.

**4. Create ansible/roles/cfk_topic/tasks/validate.yml** -- Governance validation per topic:
- Task "Extract SLA tier for {{ topic_item.metadata.name }}" -- set_fact `_topic_sla_tier` from `topic_item.metadata.labels['fsi.sla-tier'] | default('standard')`
- Task "Validate topic name governance for {{ topic_item.metadata.name }}" -- assert using `topic_item.metadata.name | fsi_validate_topic_name`
- Task "Derive config from SLA tier for {{ topic_item.metadata.name }}" -- set_fact:
  - `_topic_partitions`: `topic_item.spec.partitionCount | default(_topic_sla_tier | fsi_sla_lookup('partitions'))` (spec override or SLA default)
  - `_topic_retention_ms`: `topic_item.spec.configs['retention.ms'] | default(_topic_sla_tier | fsi_sla_lookup('retention_ms'))`
  - `_topic_min_isr`: `sla_tiers[_topic_sla_tier].min_insync_replicas`
  - `_topic_cleanup_policy`: `topic_item.spec.configs['cleanup.policy'] | default('delete')`

This MUST match the cp_topic validate.yml logic exactly to ensure governance parity.

**5. Create ansible/roles/cfk_topic/tasks/generate.yml** -- KafkaTopic CRD application:
- Task "Apply KafkaTopic CRD for {{ topic_item.metadata.name }}" using `kubernetes.core.k8s`:
  ```yaml
  kubernetes.core.k8s:
    state: present
    definition:
      apiVersion: "{{ cfk_topic_api_version }}"
      kind: KafkaTopic
      metadata:
        name: "{{ topic_item.metadata.name }}"
        namespace: "{{ cfk_topic_namespace }}"
        labels: "{{ topic_item.metadata.labels | default({}) }}"
      spec:
        replicas: "{{ cfk_replication_factor }}"
        partitionCount: "{{ _topic_partitions | int }}"
        kafkaClusterRef:
          name: "{{ cfk_kafka_cluster_name }}"
        configs:
          cleanup.policy: "{{ _topic_cleanup_policy | string }}"
          retention.ms: "{{ _topic_retention_ms | string }}"
          min.insync.replicas: "{{ _topic_min_isr | string }}"
  register: _cfk_topic_result
  ```
- CRITICAL: All config values use `| string` filter per Research Pitfall 2 (CFK requires string-typed configs).
- CRITICAL: `namespace` is always set per Research Pitfall 3.
- Task "Report KafkaTopic result for {{ topic_item.metadata.name }}" using debug.
