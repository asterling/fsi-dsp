Schema Registry REST API endpoints:
- POST /subjects/{subject}/versions -> register schema (body: {schema, schemaType, metadata: {properties: {}}})
- POST /compatibility/subjects/{subject}/versions/latest?verbose=true -> {is_compatible, messages}
- GET  /subjects/{subject}/versions/latest -> 200 (exists) or 404 (new subject)
- PUT  /config/{subject} -> set compatibility mode (body: {compatibility: "MODE"})
- GET  /config/{subject} -> get current compatibility mode

Content-Type for all SR API calls: application/vnd.schemaregistry.v1+json

    3. On failure, `ansible.builtin.fail` with the script's stdout/stderr output.
    4. Skip this task if `cp_schemas_dir` is empty (schemas provided inline).

    **tasks/compatibility.yml** -- Per-schema compatibility pre-check. Receives `schema_item` loop var. Must:
    1. Build auth headers: if `cp_sr_token` is set, `Authorization: "Bearer {{ cp_sr_token }}"`. Else use `url_username`/`url_password` with `force_basic_auth: true`.
    2. Set subject compatibility mode from SLA tier: PUT `{{ cp_sr_url }}/config/{{ schema_item.subject }}` with body `{"compatibility": "{{ schema_item.sla_tier | fsi_sla_lookup('compatibility') }}"}`. Content-Type: `application/vnd.schemaregistry.v1+json`. Status codes: [200]. Use `retries: 3`, `delay: 5` for transient errors.
    3. Check if subject has existing versions: GET `{{ cp_sr_url }}/subjects/{{ schema_item.subject }}/versions/latest` with `status_code: [200, 404]`.
    4. If subject exists (200), check compatibility: POST `{{ cp_sr_url }}/compatibility/subjects/{{ schema_item.subject }}/versions/latest?verbose=true` with body `{"schema": "{{ schema_item.schema_content | to_json }}", "schemaType": "AVRO"}`. Content-Type: `application/vnd.schemaregistry.v1+json`.
    5. Parse response: if `is_compatible` is false, register an error with the messages. Use `ansible.builtin.set_fact` to add to a `_compat_failures` list.
    6. If subject does not exist (404), skip compatibility check (first registration is always compatible).

    **tasks/register.yml** -- Per-schema registration. Receives `schema_item` loop var. Must:
    1. Build the registration request body. The `schema` field must be a JSON-escaped string (use `schema_item.schema_content | to_json` to produce the escaped string).
    2. If `cp_schema_metadata_enabled` is true, include metadata properties matching the Terraform `schema_metadata` local from `modules/topic/main.tf`:

       ```json
       {
         "schema": "{{ schema_item.schema_content | to_json }}",
         "schemaType": "AVRO",
         "metadata": {
           "properties": {
             "owner": "{{ schema_item.owner | default('') }}",
             "sla-tier": "{{ schema_item.sla_tier | default('standard') }}",
             "data-classification": "{{ schema_item.data_classification | default('internal') }}",
             "domain": "{{ schema_item.domain | default('') }}",
             "application": "{{ schema_item.application | default('') }}",
             "pii": "{{ schema_item.pii | default('false') }}",
             "pii-fields": "{{ schema_item.pii_fields | default([]) | join(',') }}"
           }
         }
       }
       ```
    3. If `cp_schema_metadata_enabled` is false, omit the metadata field entirely.
    4. POST to `{{ cp_sr_url }}/subjects/{{ schema_item.subject }}/versions` with `body_format: json`, Content-Type `application/vnd.schemaregistry.v1+json`, `status_code: [200]`.
    5. Use `retries: 3`, `delay: 5` for transient errors.
    6. Track whether the schema was actually new (compare returned `id` against previous latest version) to set `changed_when` accurately.

    **tasks/check.yml** -- Check-mode report per schema. Must:
    1. Use `check_mode: false` on all uri tasks.
    2. GET current subject version: `{{ cp_sr_url }}/subjects/{{ schema_item.subject }}/versions/latest` with `status_code: [200, 404]`.
    3. If exists, run compatibility check (same as compatibility.yml step 4).
    4. Report via `ansible.builtin.debug`: WOULD REGISTER (new subject), WOULD UPDATE (compatible change), or WOULD FAIL (incompatible).
    5. Use `changed_when` to signal planned changes.
