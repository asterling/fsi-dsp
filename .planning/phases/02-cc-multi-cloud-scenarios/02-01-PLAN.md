**Azure-specific README details:**
- Prerequisites: Azure subscription, Resource Group for Terraform state, Storage Account with container
- Backend setup: "Create storage account and container, or use existing. Update backend block in main.tf."
- Notes: "Azure AD/Entra ID OAuth tokens work against both production and DR clusters -- no credential swap during failover."

**AWS-specific README details:**
- Prerequisites: AWS account with S3 bucket and DynamoDB table for state locking
- Backend setup: "Create S3 bucket with versioning enabled and DynamoDB table with `LockID` as partition key. Update backend block in main.tf."
- Backend setup commands:
  ```
  aws s3api create-bucket --bucket fsi-terraform-state --region us-east-1
  aws s3api put-bucket-versioning --bucket fsi-terraform-state --versioning-configuration Status=Enabled
  aws dynamodb create-table --table-name fsi-terraform-locks --attribute-definitions AttributeName=LockID,AttributeType=S --key-schema AttributeName=LockID,KeyType=HASH --billing-mode PAY_PER_REQUEST
  ```
- Notes: "AWS PrivateLink requires AZ ID mapping between your VPC and Confluent Cloud."

**GCP-specific README details:**
- Prerequisites: GCP project with Cloud Storage bucket
- Backend setup: "Create GCS bucket or use existing. GCS provides built-in state locking -- no additional infrastructure needed."
- Backend setup commands:
  ```
  gsutil mb -l us-east1 gs://fsi-terraform-state
  gsutil versioning set on gs://fsi-terraform-state
  ```
- Notes: "Private Service Connect (PSC) uses a single IP with manual DNS configuration."
