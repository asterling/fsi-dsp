# Phase 5 — UI Design Contract

> Visual and interaction contract for observability dashboard templates. Generated by gsd-ui-researcher.
>
> **Note:** This phase produces dashboard template files (JSON, XML) for 6 third-party observability providers -- NOT a web application. The "UI" contract defines the visual consistency rules that dashboard templates must follow across all providers so operators get a uniform experience regardless of which observability platform their organization uses.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (no web frontend) |
| Preset | not applicable |
| Component library | not applicable -- native provider widgets |
| Icon library | not applicable -- provider-native icons |
| Font | Provider default (each platform controls its own font rendering) |

**Rationale:** Phase 5 deliverables are config-as-code dashboard templates imported into Grafana, Dynatrace, Datadog, Splunk, New Relic, and IBM Instana. Visual rendering is controlled by each provider's platform. This contract governs structural layout, naming, color semantics, and threshold consistency -- not CSS or component styling.

---

## Dashboard Layout Contract

All 6 providers must implement an identical 5-panel structure. Source: CONTEXT.md D-01.

| Panel Position | Panel Name | Primary Metric | Drill-Down |
|----------------|------------|----------------|------------|
| 1 (top-left) | Cluster Health | Broker count, under-replicated partitions, active controller | Per-broker detail |
| 2 (top-right) | Consumer Lag | Consumer group lag (records behind) | Per-partition lag by consumer group (D-12) |
| 3 (middle-left) | Connect Status | Connector state (RUNNING/PAUSED/FAILED) | Per-task status via REST API (D-10, D-15) |
| 4 (middle-right) | DR Readiness | Mirror lag per topic (seconds) | Primary vs mirror topic comparison (D-11) |
| 5 (bottom, full-width) | Flink Jobs | Stub: checkpoint duration, backpressure, throughput | Stub -- wired in Phase 6 (D-03) |

### Domain Aggregation (D-02, D-09)

- Top-level view shows metrics aggregated by domain prefix (e.g., `corebanking.*`, `fraud.*`, `compliance.*`)
- Drill-down reveals individual topic metrics within the selected domain
- Domain prefix derived from topic naming convention: `{domain}.{application}.{version}.{entity}` (ADR-007)
- Wildcard queries use domain prefix as grouping key

### Auto-Discovery Rules (D-09, D-10)

- Topic auto-discovery: wildcard match on topic name prefix -- new topics matching existing domain prefixes appear automatically without dashboard edits
- Connector auto-discovery: poll Connect REST API `/connectors` endpoint -- new connectors appear automatically
- Mirror topics shown alongside primary topics with visual distinction (D-11)

## Spacing Scale

Not applicable for provider-native dashboard templates. Each provider controls widget spacing.

**Dashboard structure spacing guidance for providers that allow layout control (Grafana, Datadog):**

| Token | Value | Usage |
|-------|-------|-------|
| Panel gap | 8px | Gap between adjacent panels in grid layout |
| Section gap | 16px | Gap between the 5 panel sections |
| Inner padding | 16px | Padding inside each panel widget |

Exceptions: Provider-native defaults take precedence where template format does not expose spacing controls.

## Typography

Not applicable for provider-native dashboard templates. Each provider controls font rendering.

**Naming consistency contract (applies to all providers):**

| Element | Convention | Example |
|---------|-----------|---------|
| Dashboard title | `FSI Kafka - {Panel Name}` | `FSI Kafka - Cluster Health` |
| Panel title | `{Metric Category}: {Specific Metric}` | `Consumer Lag: Records Behind` |

| Threshold label | `{Tier} - {Level}` | `critical - warn`, `standard - alert` |
| Metric alias | `{domain}.{metric_short_name}` | `corebanking.consumer_lag` |

## Color

### Threshold Color Coding (D-04)

All 6 providers must use the same semantic color mapping for SLA-tier threshold visualization. Source: ADR-008.

| State | Hex | RGB | Usage |
|-------|-----|-----|-------|
| OK (green) | `#22C55E` | 34, 197, 94 | Metric within normal range (below warn threshold) |
| Warning (yellow) | `#EAB308` | 234, 179, 8 | Metric exceeds warn threshold but below alert threshold |
| Alert (red) | `#EF4444` | 239, 68, 68 | Metric exceeds alert threshold -- operator action required |
| Unknown/No Data (gray) | `#6B7280` | 107, 114, 128 | Metric unavailable, data gap, or Flink stub panels |

### Mirror Topic Visual Distinction (D-11)

| Element | Color/Style | Usage |
|---------|-------------|-------|
| Primary topic | Provider default text color | Normal topic metrics display |
| Mirror topic | `#3B82F6` (blue) or provider equivalent | Mirror/DR topic metrics -- visually distinct from primary |

### Connect Connector State Colors (D-10)

| State | Hex | Label |
|-------|-----|-------|
| RUNNING | `#22C55E` | Healthy connector |
| PAUSED | `#EAB308` | Paused (possibly during DR) |
| FAILED | `#EF4444` | Failed -- requires attention |
| UNASSIGNED | `#6B7280` | Not yet assigned to worker |

### SLA Tier Color Badges

When displaying SLA tier classification in dashboard panels:

| Tier | Badge Color | Hex |
|------|-------------|-----|
| critical | Red | `#EF4444` |
| compliance | Purple | `#8B5CF6` |
| standard | Blue | `#3B82F6` |
| best-effort | Gray | `#6B7280` |

Accent reserved for: threshold violation lines on charts, SLA tier badge indicators, connector state indicators, and mirror topic identification markers.

## SLA Tier Alert Thresholds (D-04, D-07)

Source: ADR-008 `docs/adr/008-dr-tier-classification.md` and `scripts/fsi-dr.sh` threshold functions.

### Mirror Lag Thresholds

| SLA Tier | Warn Threshold | Alert Threshold | Template Variable (warn) | Template Variable (alert) |
|----------|---------------|-----------------|--------------------------|---------------------------|
| critical | 30 seconds | 60 seconds | `{{MIRROR_LAG_WARN_CRITICAL}}` | `{{MIRROR_LAG_ALERT_CRITICAL}}` |
| standard | 5 minutes (300s) | 15 minutes (900s) | `{{MIRROR_LAG_WARN_STANDARD}}` | `{{MIRROR_LAG_ALERT_STANDARD}}` |
| best-effort | 1 hour (3600s) | 4 hours (14400s) | `{{MIRROR_LAG_WARN_BESTEFFORT}}` | `{{MIRROR_LAG_ALERT_BESTEFFORT}}` |
| compliance | 10 seconds | 30 seconds | `{{MIRROR_LAG_WARN_COMPLIANCE}}` | `{{MIRROR_LAG_ALERT_COMPLIANCE}}` |

### Consumer Lag Thresholds

| SLA Tier | Warn Threshold (records) | Alert Threshold (records) |
|----------|-------------------------|---------------------------|
| critical | 1,000 | 5,000 |
| standard | 10,000 | 50,000 |
| best-effort | 100,000 | 500,000 |
| compliance | 500 | 2,000 |

### Connect Task Failure Thresholds

| Condition | Threshold | Action |
|-----------|-----------|--------|
| Any task FAILED | 1 task | Alert (all tiers) |
| Task restart count | 3 restarts in 15 minutes | Warn |

### Default Template Variable Values (D-07)

Pre-filled from ADR-008. Teams override before import.

| Variable | Default Value | Description |
|----------|--------------|-------------|
| `{{DOMAIN_PREFIX}}` | `*` (all domains) | Topic domain filter pattern |
| `{{CLUSTER_ID}}` | (empty -- must fill) | Target Kafka cluster ID |
| `{{ENVIRONMENT}}` | `prod` | Environment label |
| `{{WARN_THRESHOLD}}` | Per SLA tier above | General warn threshold |
| `{{ALERT_THRESHOLD}}` | Per SLA tier above | General alert threshold |
| `{{CONNECT_REST_URL}}` | `http://connect.internal:8083` | Connect REST API endpoint |
| `{{CC_METRICS_API_KEY}}` | (empty -- must fill) | CC Metrics API authentication |
| `{{JMX_EXPORTER_PORT}}` | `9101` | JMX exporter port (CFK/CP) |

## Template Format Per Provider (D-05)

| Provider | Directory | Dashboard Format | Alert Format | Import Mechanism |
|----------|-----------|-----------------|--------------|------------------|
| Dynatrace | `observability/dynatrace/` | JSON (Dashboard API payload) | JSON (Custom alerting profile) | Dynatrace API `POST /api/config/v1/dashboards` |
| Grafana | `observability/grafana/` | JSON (Grafana dashboard model) | YAML (Grafana alerting rules) | Grafana UI import or API `POST /api/dashboards/db` |
| Datadog | `observability/datadog/` | JSON (Dashboard API payload) | JSON (Monitor definition) | Datadog API `POST /api/v1/dashboard` |
| Splunk | `observability/splunk/` | XML (Simple XML dashboard) | JSON (Saved search / alert) | Splunk Web UI import or REST API |
| New Relic | `observability/newrelic/` | JSON (NerdGraph dashboard mutation) | JSON (NRQL alert condition) | NerdGraph API mutation |
| IBM Instana | `observability/instana/` | JSON (Custom dashboard payload) | JSON (Alert configuration) | Instana API `POST /api/custom-dashboards` |
